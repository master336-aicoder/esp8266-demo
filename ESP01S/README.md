## 项目简介

本项目是 AutoWifiConfig 固件的 **ESP-01S 精简版**，针对 ESP-01S 模块的硬件特性（1MB Flash、仅 2 个可用 GPIO、无 DHT 传感器）进行了专门优化。保留了核心的自动配网、Web 管理、MQTT 上报和 NTP 时间同步功能，同时移除了不必要的组件以适应有限的 Flash 空间。

**适用场景：**
- 智能家居最小节点（单路继电器 / 单路传感器）
- WiFi 远程开关
- 环境数据采集上报
- MQTT 物联网终端

## 硬件说明

### ESP-01S 引脚图

```
          ┌─────────────┐
   TXD ───┤ TXD     GND ├─── GND
   GPIO2 ─┤ GPIO2   GPIO0 ├─── GPIO0
   CH_PD ─┤ CH_PD   RXD ├─── RXD
   VCC ───┤ VCC     RST ├─── RST
          └─────────────┘
              ESP-01S
```

### 引脚定义

| 引脚 | 名称 | 功能说明 |
|------|------|----------|
| 1 | TXD / GPIO1 | 串口发送（调试输出），不可用作普通 GPIO |
| 2 | GPIO2 | 通用 I/O，板载 LED，**推荐使用** |
| 3 | CH_PD / EN | 使能引脚，**必须接 3.3V 高电平**才能工作 |
| 4 | VCC | 电源正极，3.3V（**严禁接 5V**） |
| 5 | RST | 复位引脚，低电平复位 |
| 6 | RXD / GPIO3 | 串口接收（调试输入），不可用作普通 GPIO |
| 7 | GPIO0 | 通用 I/O，**启动时必须为高电平**，低电平进入下载模式 |
| 8 | GND | 电源地 |

### 可用 GPIO

ESP-01S 真正可用作通用 I/O 的只有 **2 个**引脚：

| GPIO | 可用 | 推荐用途 | 注意事项 |
|------|------|----------|----------|
| GPIO0 | ✅ | 输入 / 输出 | 启动时必须为高电平，否则进入下载模式无法启动 |
| GPIO2 | ✅ | 状态 LED / 输出 | 板载 LED，低电平点亮，启动时需为高电平 |
| GPIO1 (TX) | ❌ | — | 串口发送，作 GPIO 会影响串口调试 |
| GPIO3 (RX) | ❌ | — | 串口接收，作 GPIO 会影响串口调试 |

### 注意事项

1. **GPIO0 启动电平**：上电时 GPIO0 必须为高电平，模块才能正常启动。如果 GPIO0 被拉低，模块会进入 **下载模式**，无法正常运行固件。
2. **GPIO2 板载 LED**：GPIO2 连接了板载 LED（低电平点亮），同时也是启动引脚，启动时必须为高电平。固件默认使用此引脚作为状态 LED。
3. **CH_PD 必须拉高**：CH_PD（EN）引脚必须接 3.3V 高电平，模块才会工作。如果悬空或拉低，模块不会启动。
4. **串口引脚不可用**：TXD（GPIO1）和 RXD（GPIO3）用于串口调试输出，不建议用作普通 GPIO，否则会丢失调试信息。
5. **供电要求**：必须使用 3.3V 供电，**严禁直接接 5V**，否则会烧毁模块。电流建议不小于 200mA。
6. **Flash 大小**：ESP-01S 通常为 **1MB Flash**，固件空间有限，已移除 DHT 等非必要功能。

## 功能特性

| 功能 | 说明 |
|------|------|
| 🔌 **自动配网** | 启动无 WiFi 信息或连接失败 → 自动进入 AP 配网模式，手机连接配网热点后通过 Web 页面配置 WiFi |
| 📊 **Web 状态页** | WiFi 连接成功后启动 Web 服务器，实时展示系统信息、WiFi 状态、GPIO 状态 |
| 🎛️ **GPIO 控制按钮化** | Web 界面支持设置 GPIO0 / GPIO2 的输入/输出模式，一键控制高低电平 |
| 📡 **MQTT 上报** | 支持 MQTT 协议上报 GPIO 状态和设备信息，可配置服务器、主题、上报间隔 |
| ⏰ **NTP 时间同步** | 自动同步网络时间，支持自定义 NTP 服务器和时区，Web 页面显示实时时钟 |
| 💡 **LED 状态指示** | 板载 LED 不同闪烁频率表示不同状态（慢闪=正常、中闪=连接中、快闪=配网模式） |
| 💾 **配置持久化** | WiFi / MQTT / NTP 配置全部保存在 EEPROM，掉电不丢失 |
| 🛡️ **高稳定性** | 经过加固优化，NTP 失败 / MQTT 断连 / 内存紧张均不会导致重启 |

## 快速开始

### 接线图：CH341A 连接方式

使用 CH341A USB 转串口模块进行烧录和调试，接线如下：

```
 CH341A          ESP-01S
─────────       ─────────
  3.3V  ──────── VCC (4脚)
  GND   ──────── GND (8脚)
  TX    ──────── RXD (6脚)
  RX    ──────── TXD (1脚)
                    │
  GND   ────┬────── GPIO0 (7脚)
            │
           [开关]  ←── 下载模式：闭合；运行模式：断开
```

**CH_PD 接线（重要！）：**
```
 ESP-01S
─────────
  CH_PD (3脚) ────┐
                   ├─── 接 3.3V（必须拉高！）
  VCC (4脚)  ────┘
```

> ⚠️ **CH_PD 必须接 3.3V**，否则模块不会启动。可以将 CH_PD 和 VCC 短接后一起接 3.3V。

**烧录时接线步骤：**
1. 先将 GPIO0 通过开关或杜邦线接 GND（拉低）
2. 再接上 VCC 上电（模块进入下载模式）
3. 烧录完成后，断开 GPIO0 与 GND 的连接
4. 重新上电，模块进入正常运行模式

### 烧录步骤

1. **硬件连接**：按照上方接线图连接 CH341A 和 ESP-01S
2. **进入下载模式**：GPIO0 接 GND → 上电
3. **编译烧录**：
   ```bash
   cd ESP01S
   pio run --target upload --upload-port COM4
   ```
4. **退出下载模式**：烧录成功后，断开 GPIO0 与 GND 的连接
5. **重启模块**：重新上电或按复位键，模块开始运行
6. **查看串口输出**：
   ```bash
   pio device monitor -b 115200
   ```

### 配网步骤

1. 设备上电后如无 WiFi 信息，**板载 LED 快速闪烁**，进入配网模式
2. 手机连接 WiFi 热点 **`ESP8266_Config`**（无密码）
3. 浏览器访问 **http://192.168.4.1**
4. 选择要连接的 WiFi，输入密码，点击"连接"
5. 设备连接成功后 LED 变为**慢闪**，配网完成
6. 浏览器访问设备 IP，进入设备状态管理页面

## GPIO 说明

ESP-01S 只有 **GPIO0** 和 **GPIO2** 两个可用的通用 I/O 引脚。

### GPIO0

| 属性 | 说明 |
|------|------|
| 引脚位置 | 第 7 脚 |
| 可用模式 | 输入 / 输出 / 输入上拉 |
| 启动要求 | **启动时必须为高电平** |
| 特殊功能 | 低电平启动 → 进入下载模式 |

**使用注意：**
- 如果外接电路将 GPIO0 拉低，模块将无法正常启动
- 用作输出时，上电瞬间会输出高电平（因内部上拉）
- 推荐用作输入或控制对启动时序不敏感的设备
- 外接继电器等设备时，建议加下拉电阻确保启动状态确定

### GPIO2

| 属性 | 说明 |
|------|------|
| 引脚位置 | 第 2 脚 |
| 可用模式 | 输入 / 输出 / 输入上拉 |
| 板载资源 | 连接板载 LED（低电平点亮） |
| 启动要求 | **启动时必须为高电平** |

**使用注意：**
- 固件默认使用此引脚作为状态 LED 指示
- 低电平点亮 LED，高电平熄灭
- 如果需要用作其他功能，可在 `config.h` 中修改 `LED_PIN` 定义
- 启动时必须为高电平，否则模块可能无法正常启动

### 引脚使用建议

| 场景 | GPIO0 | GPIO2 |
|------|-------|-------|
| 单路继电器控制 | 继电器（输出） | 状态 LED |
| 单路传感器输入 | 传感器（输入） | 状态 LED |
| 两路输出 | 输出 2 | 输出 1 / LED |
| 一入一出 | 输入 | 输出 / LED |

## 编译与烧录

### PlatformIO 命令

```bash
# 进入项目目录
cd ESP01S

# 编译
pio run

# 烧录（修改串口号为实际端口）
pio run --target upload --upload-port COM4

# 查看串口输出
pio device monitor -b 115200

# 清理编译产物
pio run --target clean

# 查看固件大小
pio run --target size
```

### 烧录注意事项

1. **进入下载模式**：烧录前必须将 **GPIO0 接 GND**，然后上电或复位，模块才能进入下载模式。
2. **正确的 Flash 配置**：ESP-01S 使用 1MB Flash，`platformio.ini` 中已配置 `board = esp01_1m` 和 `eagle.flash.1m64.ld`，请勿修改。
3. **烧录速度**：默认使用 9600 波特率烧录，如遇烧录不稳定可尝试降低速率。
4. **供电稳定**：烧录过程中确保供电稳定，建议使用 USB 转串口模块的 3.3V 输出，电流不小于 200mA。
5. **烧录完成后**：务必断开 GPIO0 与 GND 的连接，然后重新上电，模块才能正常运行固件。
6. **串口冲突**：烧录时如果其他程序占用了串口（如串口监视器），会导致烧录失败，请先关闭串口监视器。

### 编译输出示例

```
RAM:   [======= ] 73.2% (used 59968 bytes from 81920 bytes)
Flash: [======  ] 58.5% (used 604232 bytes from 1032192 bytes)
```

- **RAM 占用约 73%** — 留足了运行空间
- **Flash 占用约 59%** — 1MB Flash 中约 600KB 用于固件，剩余空间用于 SPIFFS 和 EEPROM

## 与 D1 开发板版本的区别

本项目基于 [AutoWifiConfig](../AutoWifiConfig/README.md) 固件，针对 ESP-01S 硬件进行了裁剪。主要区别如下：

| 对比项 | D1 开发板版 (AutoWifiConfig) | ESP-01S 版 (本项目) |
|--------|------------------------------|---------------------|
| **Flash 大小** | 4MB | 1MB |
| **可用 GPIO 数量** | 11 个 (GPIO0~5, GPIO12~16) | 2 个 (GPIO0, GPIO2) |
| **板载 LED** | GPIO2 (D4) | GPIO2 |
| **DHT 温湿度** | ✅ 支持 | ❌ 已移除（节省 Flash） |
| **自动配网** | ✅ 支持 | ✅ 支持 |
| **Web 状态页** | ✅ 完整功能 | ✅ 完整功能（GPIO 减少为 2 个） |
| **MQTT 上报** | ✅ 支持 | ✅ 支持 |
| **NTP 时间同步** | ✅ 支持 | ✅ 支持 |
| **LED 状态指示** | ✅ 支持 | ✅ 支持 |
| **配置持久化** | ✅ EEPROM | ✅ EEPROM |
| **Web GPIO 控制** | 11 个引脚 | 2 个引脚 |

### 代码差异

主要差异在 `main.cpp` 中：
- 移除了 `DHTManager.h` 的引用和初始化
- `platformio.ini` 中移除了 DHT 相关库依赖
- `board` 改为 `esp01_1m`，Flash 布局改为 `eagle.flash.1m64.ld`
- 烧录波特率设为 9600（ESP-01S 更稳定）

## 常见问题

### Q: 烧录失败怎么办？

A: 按以下步骤排查：

1. **检查下载模式**：确认 GPIO0 是否可靠地接到了 GND，然后再上电。可以尝试断电 → 接 GPIO0 到 GND → 再上电的顺序。
2. **检查接线**：确认 TX 接 RXD、RX 接 TXD（交叉连接），GND 是否共地。
3. **检查 CH_PD**：确认 CH_PD（EN）引脚是否已接 3.3V 拉高。
4. **检查串口号**：确认串口号是否正确，在设备管理器中查看。
5. **降低烧录速率**：在 `platformio.ini` 中修改 `upload_speed` 为更低的值（如 57600 或 9600）。
6. **关闭串口监视器**：烧录时如果串口监视器正在运行，会占用串口导致烧录失败。
7. **供电问题**：尝试使用更好的 USB 线或电源，确保 3.3V 供电稳定。
8. **重新插拔**：有时候重新插拔 USB 可以解决识别问题。

### Q: 烧录后模块不启动，LED 不亮？

A: 大概率是 **忘记断开 GPIO0 与 GND 的连接**：

1. 烧录完成后，必须断开 GPIO0 和 GND 的连接
2. 重新上电或按复位键，模块才会正常启动
3. 如果 GPIO0 仍然接 GND，模块会一直停留在下载模式

### Q: 连不上 WiFi 怎么办？

A:

1. **确认 WiFi 频段**：ESP8266 只支持 2.4GHz WiFi，不支持 5GHz
2. **检查密码**：确认密码输入正确，注意大小写
3. **信号强度**：ESP-01S 天线较小，尽量靠近路由器
4. **查看串口日志**：通过串口监视器查看具体的连接失败原因
5. **复位重试**：按复位键重启模块，重新尝试连接
6. **清除配置重配**：如果配置错误，可以通过重新烧录或在代码中清除 EEPROM 配置

### Q: 时间不对怎么办？

A:

1. **确认网络连通**：NTP 同步需要设备能访问互联网
2. **检查 NTP 服务器**：默认使用 `ntp.aliyun.com`，如网络受限可尝试更换为其他 NTP 服务器
3. **手动同步**：在 Web 页面的 NTP 设置页点击"立即同步"按钮
4. **等待首次同步**：首次同步可能需要几十秒，请耐心等待
5. **检查时区**：确认时区设置正确（默认东 8 区，即 +8）

### Q: 找不到 ESP8266_Config 配网热点？

A:

1. **确认配网模式**：观察板载 LED 是否快速闪烁（配网模式），如果是慢闪则已连接 WiFi
2. **靠近设备**：ESP-01S 的 AP 模式信号较弱，尽量靠近设备再搜索
3. **检查供电**：确保供电充足，电压不足会导致 WiFi 功能异常
4. **重启设备**：按复位键重启，观察 LED 状态变化

### Q: MQTT 连接失败怎么办？

A:

1. **检查服务器地址和端口**：在 Web 页面的 MQTT 配置页确认配置正确
2. **确认网络连通**：设备能否访问 MQTT 服务器所在网络
3. **检查用户名密码**：确认 MQTT 服务器的认证信息正确
4. **查看上报日志**：在 MQTT 配置页底部查看最近 20 条上报记录
5. **测试服务器**：使用其他 MQTT 客户端工具测试服务器是否正常

### Q: CH_PD 不接可以吗？

A: **不可以！** CH_PD（EN）是 ESP8266 的使能引脚，必须接高电平（3.3V）模块才会工作。如果悬空，模块不会启动，表现为 LED 不亮、串口无输出、搜索不到 WiFi 热点。

### Q: ESP-01S 可以接 5V 电源吗？

A: **绝对不可以！** ESP-01S 是 3.3V 供电的模块，直接接 5V 会烧毁芯片。必须使用 3.3V 电源供电，如果使用 USB 转串口模块，确保选择 3.3V 输出档位。

### Q: 如何恢复出厂设置（清除 WiFi 配置）？

A: 有两种方式：
1. 重新烧录固件（EEPROM 数据可能保留，取决于烧录设置）
2. 在代码中调用 `g_wifiMgr.clearConfig()` 然后重启

最简单的方式是重新烧录时勾选清除 Flash 选项，或在配网模式下连接失败 3 次后会自动重新进入配网模式。
