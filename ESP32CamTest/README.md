# ESP32 摄像头测试程序

基于 ESP32 + OV2640 摄像头的 Web 视频流测试程序。

## 功能特性

- 📹 **实时视频流** — MJPEG 格式，浏览器直接播放
- 📸 **拍照保存** — 一键下载 JPEG 图片
- 🖼️ **13 档分辨率** — 从 96x96 到 UXGA (1600x1200)
- ⚙️ **JPEG 质量调节** — 4~63 可调
- 🎨 **15 种图像特效** — 负片/灰度/复古/黑白等
- 📊 **系统状态监控** — WiFi/内存/PSRAM/运行时间
- 🌐 **Web 控制界面** — 响应式设计，手机也能用

## 硬件要求

- **ESP32-CAM 开发板**（ESP32-S + OV2640 摄像头）
- **USB-TTL 下载器**（CH340/CP2102/FTDI 等）
- **杜邦线** 若干（母对母）
- PSRAM（本模块已内置 2MB PSRAM）

> ⚠️ **注意**：ESP32-CAM 本身没有 USB 接口，必须通过 USB-TTL 下载器连接电脑烧录！

### 支持的摄像头模块

| 模块类型 | CAMERA_MODEL | 说明 |
|----------|--------------|------|
| AI-Thinker ESP32-CAM | 0 | 最常见的 ESP32-CAM 模块（本项目默认） |
| ESP32-WROVER-KIT | 1 | 官方开发板 |
| M5Stack Timer Camera | 2 | M5Stack 计时器相机 |
| 自定义 | 3 | 自行修改引脚定义 |

### 硬件规格

| 项目 | 参数 |
|------|------|
| 模块 | ESP32-S |
| CPU | ESP32 240MHz 双核 |
| Flash | 32Mbit (4MB) |
| RAM | 520KB 内部 + 2MB PSRAM |

## 接线说明

### USB-TTL 下载器接线

ESP32-CAM 没有 USB 接口，需要用 USB-TTL 下载器烧录。

| ESP32-CAM | USB-TTL 下载器 | 说明 |
|-----------|---------------|------|
| **5V** | **5V** | 电源（必须 5V，不能接 3.3V！） |
| **GND** | **GND** | 共地 |
| **U0R (GPIO3)** | **TXD** | ESP32 接收 ← TTL 发送 |
| **U0T (GPIO1)** | **RXD** | ESP32 发送 → TTL 接收 |

> 💡 **交叉接线**：ESP32 的 TX 接 TTL 的 RX，ESP32 的 RX 接 TTL 的 TX。

### 进入下载模式

烧录固件时必须进入下载模式：

1. **接线**：按上表接好 5V、GND、TX、RX
2. **短接 IO0 到 GND**：用杜邦线把 **IO0 (GPIO0)** 和 **GND** 短接
3. **复位**：按一下 RST 按钮（或重新上电）
4. **开始烧录**：执行烧录命令
5. **烧录完成后**：断开 IO0 和 GND 的短接，再按 RST 重启运行

> ⚠️ **重要**：IO0 接 GND = 下载模式；IO0 悬空 = 正常运行模式。

### 接线示意图

```
ESP32-CAM          USB-TTL 下载器
──────────         ────────────
    5V ──────────────── 5V
   GND ──────────────── GND
  U0R ──────────────── TXD
  U0T ──────────────── RXD

  IO0 ────┐
          ├── 短接进入下载模式
  GND ────┘
```

## 快速开始

### 1. 修改 WiFi 配置

编辑 `src/main.cpp`，修改顶部的 WiFi 配置：

```cpp
const char* WIFI_SSID = "你的WiFi名称";
const char* WIFI_PASSWORD = "你的WiFi密码";
```

### 2. 选择摄像头模块

默认是 AI-Thinker ESP32-CAM（最常见）。如果是其他模块，修改：

```cpp
#define CAMERA_MODEL 0  // 0=AI-Thinker, 1=WROVER-KIT, 2=M5Stack, 3=自定义
```

### 3. 接线

按照上面的 [接线说明](#接线说明) 接好 USB-TTL 下载器：

- 5V → 5V（必须 5V！）
- GND → GND
- U0R → TXD
- U0T → RXD
- IO0 短接 GND（进入下载模式）

### 4. 编译

```bash
# 进入项目目录
cd ESP32CamTest

# 编译固件
python -m platformio run
```

编译成功后会显示内存占用：
```
RAM:   [==        ]  15.2%
Flash: [====      ]  44.5%
```

### 5. 烧录固件

1. 确认 IO0 已短接 GND
2. 按一下 RST 按钮（或重新上电）
3. 执行烧录命令：

```bash
# 烧录（修改串口号为你的 TTL 下载器端口）
python -m platformio run --target upload --upload-port COM4
```

4. 烧录成功后，**断开 IO0 和 GND 的短接**
5. 按一下 RST 按钮，设备开始运行新固件

### 6. 查看串口输出

```bash
# 打开串口监视器
python -m platformio device monitor -b 115200 -p COM4
```

正常启动后会输出：
```
[WiFi] 连接成功！
[WiFi] IP 地址: 192.168.x.x
[WEB] 访问地址: http://192.168.x.x/
```

### 7. 访问摄像头

浏览器访问串口输出的 IP 地址，即可看到摄像头画面。

- WiFi 连接状态
- IP 地址
- 当前分辨率
- PSRAM 检测状态
- 可用内存
- 运行时间

## 常见问题

### 串口打不开 / "连到系统上的设备没有发挥作用"

这是 ESP32-CAM 最常见的问题，通常原因和解决方法：

| 原因 | 解决方法 |
|------|----------|
| 供电不足 | **必须接 5V**，不能接 3.3V。ESP32-CAM 工作电流大（180~310mA），3.3V 供电不足 |
| TX/RX 接反了 | ESP32 的 TX 接 TTL 的 RX，ESP32 的 RX 接 TTL 的 TX（交叉接线） |
| 没有共地 | ESP32-CAM 的 GND 必须和 TTL 的 GND 接在一起 |
| USB 线问题 | 换一根数据线（不是充电线） |
| USB 口供电不足 | 插到电脑后面的 USB 口，或使用带供电的 USB HUB |
| 驱动问题 | 重新安装 CH340/CP2102 驱动 |

### 烧录失败 / "Timed out waiting for packet header"

1. 确认 **IO0 已短接 GND**
2. 按一下 RST 按钮后再点击烧录
3. 检查 TX/RX 是否接反
4. 降低烧录波特率（platformio.ini 中修改 `upload_speed`）
5. 确保供电充足（必须 5V）

### 烧录成功后设备不启动

烧录完成后必须：
1. **断开 IO0 和 GND 的短接**
2. 按一下 RST 按钮重启

如果不断开 IO0，设备会一直停在下载模式，不会运行固件。

### 摄像头初始化失败

1. 检查摄像头排线是否插紧（FPC 插座，注意方向）
2. 确认 `CAMERA_MODEL` 设置为 0（AI-Thinker ESP32-CAM）
3. 检查供电是否充足（5V）
4. 查看串口输出的错误代码

### 画面卡顿 / 帧率低

1. 降低分辨率
2. 提高 JPEG 质量数值（降低画质，减小文件大小）
3. 确保有 PSRAM（本模块已内置）
4. 检查 WiFi 信号强度
5. 减少同时连接的客户端数量

### 找不到设备 IP

1. 查看串口输出
2. 在路由器管理页面查找设备
3. 确保设备和电脑在同一个 WiFi 网络
4. 检查 WiFi 名称和密码是否正确

### 没有 PSRAM 怎么办

没有 PSRAM 也能工作，但只能使用较低分辨率（QQVGA~QVGA），且帧率较低。
本 ESP32-CAM 模块已内置 2MB PSRAM，无需担心。

### WiFi 连不上

1. 检查 WiFi 名称和密码是否正确
2. 确认是 2.4GHz WiFi（ESP32 不支持 5GHz WiFi）
3. 查看串口输出的错误信息
4. 确认 WiFi 路由器没有 MAC 地址过滤
